Reduction 四层架构

两条设计主线：流式 TTS 把“首句出声”的延迟压到最低；乐音和“好的”包住每一次录音：乐音响起就是开麦，乐音持续就是仍在录，“好的”就是关麦。
四层只允许向下调用、向上发事件。对话核心随进程存活，不依赖界面：熄屏、界面被系统回收，唤醒和对话照常。语音状态机是一个纯函数 VoiceMachine.next(状态, 事件)。

每层一句话职责 + 归属包。模块名即类名或文件名。

2. 语音状态机（VoiceMachine）

录音状态由 PREPARING → LISTENING → TURN_ACK 三段组成，进出各只有一条路。UI 层只订阅这一份状态。

stateDiagram-v2
    direction TB
    [*] --> IDLE
    IDLE --> PREPARING: Hi Reduction / 耳机单击
    state "录音" as REC {
        PREPARING --> LISTENING: 麦克风就绪，乐音响起
        LISTENING --> TURN_ACK: 听到“完毕” / 耳机单击 / 点结束 / 满 60s / 12s 没人说话 / 取消 / 出错
    }
    PREPARING --> IDLE: 取消 / 麦克风打不开（无声）
    TURN_ACK --> REPLYING: 识别到文本
    TURN_ACK --> IDLE: 没人说话 / 没听清 / 取消 / 出错
    REPLYING --> PREPARING: Hi Reduction / 耳机单击（打断）
    REPLYING --> IDLE: 回复播完 / 回复失败
乐音
含义：麦克风开着，正在录，可以说。
说“Hi Reduction”或单击耳机可开始录音。使用耳机麦克风常驻唤醒时，录音沿用已建立的蓝牙通话链路。开始录音时会播放一个微弱的和弦，各音以不同的慢速率起伏。持续收到麦克风音频帧时，和弦每半秒续播一次。收音中断后，和弦在 1.5 秒内停下。耳机和外放音量相同。
“好的”
含义：麦克风已关。
离开录音状态的唯一出口，无论原因：说完、没人说话、取消、出错。结束的同一刻乐音停、“好的”响，与文本定稿、LLM 请求并行；首句 TTS 排在它后面接着播。蓝牙等“好的”完全播出之后才切回听歌模式。
一个队列
乐音、“好的”、朗读都排进同一个队列、写入同一条流。顺序由入队顺序决定，衔接处是相邻的两个采样，不存在重叠或空白。
保证方式
状态机是纯函数，规则可以直接调用来验证。VoiceMachineTest 逐条检查每个转换，并用任意事件顺序验证：每次开始的录音恰好以一个“好的”结束，没开始的录音不会说“好的”，空闲时一定在听唤醒词。

3. 每个状态里，每层各做什么

横向是时间，纵向是分层。按列看一个状态的完整行为，按行检查一层有没有越界。

IDLE待唤醒 PREPARING准备麦克风 LISTENING聆听 TURN_ACK“好的” REPLYING回复中 · 流式 TTS
UI 层 状态条为空 状态条“准备中”，录音条出现；唤醒时震动 实时字幕；“结束”按钮 状态条“好的”；有文本时出用户气泡 流式文字，每次工具调用一行（摘要、完成时间、状态）；状态条“回复中 / 播放中”
功能层 等唤醒词事件 准备麦克风；就绪即开始录音 TurnEndpointer 逐帧判定起止：听到“完毕”立刻结束，停顿不结束；12s 没人开口则退出；满 60s 强制结束；每半秒音频为蜂鸣续命一次 播“好的”；同时定稿文本，文本一到就交给 Conversation ReplyStreamer：整条回复都念；首段在第一个逗号（≥ 6 字）切出去合成；之后按句切，单段 ≤ 200 字；播放时预合成后续 3 段
模型层 KWS 持续跑 无模型调用 Silero VAD（人声）+ KWS（结束词“完毕”）在本地逐帧运行；滚动 ASR 只出实时字幕，不参与结束判定 滚动结果直接定稿，或整段识别；随后 LLM 首 token LLM token 流；TTS 逐段合成，命中缓存直接返回
硬件层 麦克风 → KWS（前台服务常驻） 唤醒监听让出麦克风，录音复用已有耳机通话链路或打开相应输入 麦克风 PCM；队列空闲时循环写入乐音 清空队列，“好的”入队；麦克风关闭；播完后归还蓝牙通话模式 朗读片段排进 AudioQueue，接在“好的”之后；耳机输出时麦克风交还 KWS 以支持打断
延迟目标 — 唤醒到乐音响起的耗时包含录音器启动，已处于监听状态的耳机可复用通话链路 — 说完 → 出声 ≤ 300ms “好的”结束 → 首句出声 ≤ 1.5s；段间无停顿

4. 状态机的接口：事件进，清单出

VoiceMachine.next(状态, 事件) → (新状态, 要做的事)。函数本身什么都不执行；执行器照清单办事，再把结果作为事件送回。每次转换在日志里是一行。

Voice IDLE + WakeWord -> PREPARING [AbortReply, PauseWake, PrepareMic(turn=1)]
Voice PREPARING + MicReady(turn=1) -> LISTENING [StartRecording(turn=1)]
Voice LISTENING + TurnSpoken(turn=1) -> TURN_ACK [SayOk(turn=1), Transcribe(turn=1)]
Voice TURN_ACK + Transcribed(1, 12 chars) -> TURN_ACK [Submit(1, 12 chars)]
Voice TURN_ACK + ReplyStarted(id=…) -> REPLYING []
Voice REPLYING + OkDone(turn=1) -> REPLYING [ReleaseRoute, ArmBargeIn]
Voice REPLYING + ReplyEnded(id=…, ok=true) -> IDLE [ResumeWake]
事件 · 来自硬件 / 模型麦克风与唤醒词WakeWord、MicReady、MicFailed、TurnSpoken、TurnSilent、Transcribed、OkDone。
事件 · 来自对话回复的起止ReplyStarted、ReplyEnded(ok)、ReplyOverdue（话发出去了却没有回复开始）。
事件 · 来自用户两个按钮UserFinish 结束本轮；UserCancel 退出对话。
清单 · 麦克风录音PrepareMic、StartRecording（同时起乐音）、FinishRecording、DiscardRecording、ReleaseRoute。
清单 · 声音与文字收尾SayOk（停乐音、播“好的”）、Transcribe、Submit（交给 Conversation）、ShowError。
清单 · 唤醒词麦克风归属PauseWake、ResumeWake、ArmBargeIn（仅耳机输出时生效）、AbortReply。

每次录音有一个编号 turn。关于录音的事件都带编号，属于更早一次录音的事件会被忽略，所以迟到的回调不会打乱当前状态。
